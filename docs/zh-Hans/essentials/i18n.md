# 国际化

::: warning 尚未发布
本页介绍的 `inputCharset` / `outputCharset` 玩家 API 计划随 `@infernus/core` `^0.16.0` 提供。**该版本尚未发布，目前也没有发布计划。** 在它发布之前，`0.15.x` 及更早版本仍使用单一的 `player.charset`，同时覆盖两个方向。
:::

`Infernus` 的国际化核心在于**字符集编码转换**，而非多语言翻译。虽然 `$t` 可以用于翻译需求，但核心功能是确保服务端（UTF-8）与玩家客户端（旧式字符集如 `ISO-8859-1` 或 `GBK`）之间的数据交换正确。大多数服务器仅服务于单一区域，因此您可能完全不需要多语言支持——但至少应了解[玩家国际化](#玩家国际化)部分，以避免乱码问题。

## VSCode 插件

[infernus-starter](https://github.com/dockfries/infernus-starter) 中的 `.vscode/extensions.json` 提供了插件安装建议。强烈建议您在 VSCode 右下角弹出提示时点击安装，以便在开发时直观地查看国际化数据。

`i18n-ally-custom-framework.yml` 和 `settings.json` 已为您配置好相关插件设置。

## 示例

### 定义语言包

语言包由 `.json` 文件组成，**以树形结构作为语言包数据的 key**。

字符串中可以包含 `%s` 作为占位符，用于动态填充数据。

#### 中文语言包

```json
{
  "server": {
    "running": "成功运行由 node.js 强力驱动的 omp 服务器",
    "connection": "连接信息：%s - %s : %s"
  }
}
```

#### 英文语言包

```json
{
  "server": {
    "running": "Successfully running an omp server powered by node.js",
    "connection": "connection information: %s - %s : %s"
  }
}
```

### 实例化

通过 `new I18n("默认区域 key", 语言包对象)` 创建国际化实例。

通常我们只需使用内部的 `$t` 函数。

`$t("语言包数据 key", [占位数组], 区域 key)` 可获取对应区域的语言包文本。

当字符串没有占位符时，可传入 `null`、`undefined` 或空数组。

不传入第三个参数则从默认区域获取数据。

```ts
import { I18n } from "@infernus/core";

// 国际化的 JSON 语言包
import zh_CN from "./locales/zh_CN.json";
import en_US from "./locales/en_US.json";

const locales = {
  zh_CN,
  en_US,
};

export const { $t } = new I18n("en_US", locales);

console.log($t("server.running"));
console.log($t("server.connection", ["127.0.0.1", "8080", "123456"]));
console.log($t("server.connection", ["127.0.0.1", "8080", "123456"], "zh_CN"));
```

### 实用函数

`I18n` 类还提供了几个实用的**静态方法**，用于字符集之间的转换：

- `encodeToBuf`
  - 将字符串转换为指定字符集的字节数组。
- `decodeFromBuf`
  - 将字节数组转换为指定字符集的字符串。
- `getValidStr`
  - 截取字节数组中的有效字符串，以第一个 `0` 字节作为字符串结尾标记。
- `convertSpecialChar`
  - 将重音拉丁字符重映射到原版 SA 字体存放其字形的字节槽位上，详见[原理](#原理)。

## 玩家国际化

每个玩家实例有三个国际化属性：`inputCharset`（输入字符集）、`outputCharset`（输出字符集）和 `locale`（区域）。默认值如下：

```ts
class Player {
  inputCharset = "ISO-8859-1";
  outputCharset = "ISO-8859-1";
  locale = "en_US";
}
```

两个字符集回答的是两个不同的问题：

- **输入：玩家发给服务器的数据。** `inputCharset` 是服务器用来解码该玩家数据的编码——名字（`GetPlayerName`）、聊天（`OnText`）、指令（`OnPlayerCommandText`）、对话框输入（`OnDialogResponse`）以及 `gpci`。
- **输出：服务器发给玩家的数据。** 服务器用 `outputCharset` 编码，玩家的客户端再用同一编码解码——消息（`SendClientMessage`）、私聊（`SendPlayerMessageToPlayer`）、对话框（`ShowPlayerDialog`）、聊天气泡（`SetPlayerChatBubble`）。

输入字符集错了，服务器读到的就是乱码（名字、聊天、指令都不对）；输出字符集错了，玩家看到的就是乱码。

`SetPlayerName` 同样用 `inputCharset` 编码，这样名字经过 `GetPlayerName` 往返一次后仍保持原样。

两者默认都是 `ISO-8859-1`，因为原版 SA 客户端两个方向只用同一种旧式编码。客户端模组则未必：它可能重绘字体，让客户端在显示时按 UTF-8 取字形，而键盘、输入法或打过补丁的输入仍产出旧式字节——反过来也一样。只有一个 `charset` 时，您只能顾一头、必定弄乱另一头；拆成两个属性，才能如实描述玩家真正在跑的客户端。

```ts
PlayerEvent.onConnect(({ player, next }) => {
  // 字体模组按 UTF-8 取字形，但客户端输入仍是 GBK
  player.inputCharset = "gbk";
  player.outputCharset = "utf8";
  return next();
});
```

给任一属性赋值都会触发 `OnPlayerCharsetChange`，事件会说明是哪一侧变了：

```ts
PlayerEvent.onCharsetChange(({ player, newCharset, oldCharset, direction, next }) => {
  console.log(player.id, direction, oldCharset, "->", newCharset);
  return next();
});
```

`locale` 决定用哪套语言包，两个字符集决定文本能否完好送达。请在玩家读到第一句话之前就把两者设好——`OnPlayerConnect` 是最早的时机；若需要探测客户端，就在探测完成后立即设置。区域可以靠 IP 推测；`inputCharset` 可以让玩家输入一段已知文本，逐个尝试候选编码，直到解出的内容对得上。这种往返只能测出输入：`outputCharset` 取决于玩家实际运行的客户端——原版、字体模组，还是 russifier。

::: tip 从 `player.charset` 迁移
`player.charset` 已被移除。若要还原旧行为，请同时赋值两个属性：

```ts
player.inputCharset = player.outputCharset = "ISO-8859-1";
```

`OnPlayerCharsetChange`（即 `PlayerEvent.onCharsetChange`）新增 `direction` 参数，指明是哪一侧发生了变化。
:::

### 允许国际化用户名

::: tip
默认情况下，游戏服务器只允许英文字母、数字和下划线组成的用户名连接。
:::

OMP 提供了新的 API，可启用或禁用用户名中的特定字节值（0–255）。

`GameMode.supportAllNickname()` **方法利用这些 API，允许所有国际化的用户名（包括中文等非 ASCII 字符）连接游戏。**

```ts
import { GameMode } from "@infernus/core";

GameMode.onInit(({ next }) => {
  GameMode.supportAllNickname();
  return next();
});
```

## 原理

:::warning
只有 `inputCharset` 与 `outputCharset` 都与玩家客户端相符，双向字符集交换才能正常工作。填错只会让对应的那个方向乱码，另一个方向不受影响。
:::

`Infernus` 底层使用 `iconv-lite` 进行字符集转换，并通过 `polyfill.amx` 拦截 `gamemode` 中的部分回调，以十进制字节数组形式返回。

服务端发往客户端的 API 会按 `outputCharset` 把 UTF-8 编码出去——`SendClientMessage`、`SendClientMessageToAll`、`SendPlayerMessageToPlayer`、`ShowPlayerDialog`、`SetPlayerChatBubble`，以及建立在它们之上的其他封装。

客户端发往服务端的回调按 `inputCharset` 解码——`OnText`、`OnPlayerCommandText`、`OnDialogResponse`，以及 `GetPlayerName`、`SetPlayerName`、`gpci`。

::: tip
字符集转换变不出目标编码里没有的字符：玩家字符集里不存在的字符仍会显示为 `?`。这是早期 SA 客户端的底层限制。使用 `ISO-8859-1` 的客户端收到 emoji 或中文，无论服务端怎么配置都只会是乱码。
:::

`GameText` 与 `TextDraw` 走另一条路：它们不套用玩家的两个字符集，而是用调用时传入的 `charset` 编码（`GameText` 默认 `win1252`，`TextDraw` 默认 `ISO-8859-1`）。客户端随后按字节值从字体贴图中取字形（可以类比前端里的精灵图），而不是把字节当作文本解码。

这两个 API 会在需要时重映射重音拉丁字符（`é`、`ñ`、`ü` 等）：原版 SA 字体把这些字形放在专门的字节槽位里，而不在 Latin-1 的对应位置，`convertSpecialChar` 负责把它们挪过去。是否重映射由 `convertSpecialChars` 控制：只有原版字体使用的编码（`win1252`、`cp1252`、`ISO-8859-1`）默认是 `true`，其他编码（如 `utf8`、`cp1251`）默认是 `false`，否则会把字节改坏。需要时显式传入覆盖：

```ts
new GameText("...", 3000, 3).forAll("cp1251", false);
new TextDraw({
  x: 10,
  y: 10,
  text: "Привет",
  charset: "cp1251",
  convertSpecialChars: false,
}).create();
```

俄文是同一套机制的另一面：russifier 是玩家装在**客户端**上的俄语化 mod，它重绘游戏字体，把西里尔字母画进原字体留给重音拉丁字符的槽位。[`@infernus/rustext`](../ecosystem) 负责服务端这一半——改写出站的 `GameText`、`TextDraw` 与 `Menu` RPC 文本，让 cp1251 字节落到该 mod 对应的字形槽位上。因此必须显式传入 `charset: "cp1251"`（上面的默认字符集会在包拿到文本之前就把西里尔字母变成 `?`），并把 `RussifierType` 设为与玩家实际安装的那套一致——各套方案的槽位布局互不相同（`SanLtd` 是默认值，另有 `OneC`、`Rush`、`MG` 等）。包本身不附带任何 russifier 资源。`@infernus/rustext` 会重写这些 RPC，因此上面的 `cp1251` 编码已经足够——`cp1251` 下重映射默认就是关闭的。广播给所有玩家的文本（`GameText.forAll`）不带玩家 id，不会被转换。

SA 重制版内部使用 UTF-8 实现，如果未来 OMP 推出重制版的联机功能，应无需额外处理。

## 终端乱码

如果使用 `pino.js` 等日志库时终端出现乱码，可尝试以下方法解决。

**PowerShell** 用户请执行以下命令（仅对当前会话有效）。

如需永久生效，请将该命令添加到 [$PROFILE](https://learn.microsoft.com/zh-cn/powershell/module/microsoft.powershell.core/about/about_profiles?view=powershell-7.4) 中。

```powershell
$OutputEncoding = [Console]::InputEncoding = [Console]::OutputEncoding = New-Object System.Text.UTF8Encoding
```

**cmd** 用户可使用以下命令启动 OMP 服务器：

```sh
cmd /c "chcp 65001 > nul & omp-server"
```

上述命令会将终端的字符集切换为 UTF-8。

其他环境请自行搜索解决方案。
